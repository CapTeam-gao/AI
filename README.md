# CapTeam AI

CapTeam AI는 캡스톤 프로젝트 팀 매칭을 위해 학생 데이터를 분석하고, 팀을 자동 생성하고, 최종 팀 결과를 요약해서 제공하는 FastAPI 기반 AI 서버입니다.

## 프로젝트 개요

이 프로젝트의 AI 파트는 다음 3가지를 핵심으로 담당합니다.

1. 학생 설문/기술 정보 기반 역량 분석
2. 분석 결과를 바탕으로 한 팀 자동 매칭
3. 최종 팀 결과 요약 및 재생성 지원

단순히 학생을 랜덤으로 나누는 것이 아니라, 기술 수준, 역할군, 협업 성향, 선호 팀원, 팀장 희망 여부 등을 함께 고려해서 더 균형 잡힌 팀 구성을 목표로 했습니다.

## 주요 기능

### 1. LLM 기반 학생 분석
학생의 기술 스택, 경험, 협업 정보 등을 바탕으로 AI가 학생별 역량을 분석합니다.

분석 결과로 다음과 같은 정보를 생성합니다.

- `skill_level`
- `stack_score`
- `strength`
- `weakness`
- `reason`
- `suggestion`
- 추천 역할(`role`)

이 과정을 통해 단순 자기소개나 기술 나열이 아니라, 실제 팀 프로젝트에 어떤 방식으로 기여할 수 있는지 해석하도록 구성했습니다.

### 2. 성향 및 협업 프로필 반영
기술 역량만 보는 것이 아니라, 설문 기반 성향 정보도 함께 반영했습니다.

예를 들어 다음 요소들을 정규화해서 팀 매칭 보조 지표로 사용합니다.

- 소통 능력
- 책임감
- 협업 성향
- 유연성
- 감정 안정성
- 리더십
- 문제 해결력
- 구현 실행력
- 학습 성장성
- 기획 정리력

이를 통해 특정 팀에 비슷한 성향만 몰리지 않도록 하고, 서로 보완 가능한 조합을 만들도록 설계했습니다.

### 3. 팀 자동 매칭
분석된 학생 데이터를 기반으로 AI가 팀을 생성합니다.

팀 매칭 시 다음 기준을 함께 고려합니다.

- 역할군 균형
- 팀 간 실력 밸런스
- 선호 팀원 반영
- 팀장 희망 여부
- 협업 성향 보완 관계
- 특정 역할군 쏠림 방지

처음에는 규칙 기반으로 1차 팀을 만들고, 이후 LLM이 필요한 경우만 팀 조합을 보정하는 구조로 구현했습니다.

### 4. 팀 결과 검증 및 재조정
팀이 생성된 뒤에는 바로 끝내지 않고, 코드로 한 번 더 검증합니다.

검증 항목 예시는 다음과 같습니다.

- 중복 배정 학생 존재 여부
- 누락 학생 존재 여부
- 없는 이름 포함 여부
- 팀 인원 초과 여부
- 팀 간 점수 차이 과다 여부
- 역할군 편중 여부
- 팀장 후보 적절성

문제가 있으면 재조정 루프를 통해 다시 수정하고, 필요 시 fallback 로직으로 안정적인 결과를 만들 수 있게 구성했습니다.

### 5. 팀 재생성 기능
관리자가 원하는 방향을 프롬프트로 전달하면, 현재 팀을 완전히 새로 만드는 것이 아니라 기존 결과를 최대한 유지하면서 필요한 부분만 수정하도록 구현했습니다.

예를 들면 다음과 같은 요청이 가능합니다.

- 특정 학생을 같은 팀으로 묶기
- 특정 역할군 분산 조정
- 팀장 재선정
- 일부 팀만 최소 변경

이 기능은 실제 운영에서 “결과를 한 번에 전부 갈아엎지 않고, 원하는 방향으로 미세 조정하고 싶다”는 요구를 반영한 부분입니다.

## API 구성

AI 서버는 FastAPI 기반으로 구성되어 있으며, 주요 엔드포인트는 다음과 같습니다.

- `GET /health`
- `GET /teams/summary`
- `POST /analysis/run`
- `POST /matching/run`
- `POST /matching/regenerate`
- `POST /matching/hackathon/run/stream`
- `POST /matching/hackathon/regenerate/stream`

백엔드가 `X-Matching-Job-Id` 헤더를 함께 보내면 캡스톤 매칭도 배치 완료마다
`POST {BACKEND_BASE_URL}/internal/matching/jobs/{jobId}/batch-complete`를 호출합니다.
이때 `X-Internal-Api-Key`는 `INTERNAL_MATCHING_API_KEY` 환경변수 값이며 백엔드와 AI 서버에
동일하게 설정해야 합니다. 로컬 예시는 `.env.example`에 있습니다.

### 팀 매칭 SSE 스트림

스트림 API는 기존 해커톤 호환 요청 본문을 그대로 사용하며, 실제 팀 생성과 재생성은 캡스톤 매칭 워크플로우로 처리합니다. 요청에는 백엔드 작업 ID를 `X-Matching-Job-Id` 헤더로 전달해야 합니다.

응답의 `Content-Type`은 `text/event-stream`이며 이벤트는 다음 순서로 전달됩니다.

1. `started`: 작업 시작과 생성/재생성 모드
2. `progress`: `ANALYZING`, `MATCHING`, `VALIDATING`, `EXPLAINING`, `SAVING` 단계
3. `team_preview`: 검증이 끝난 기본 팀 구성
4. `team_update`: 강점과 약점 생성이 끝난 팀
5. `team_ready`: 배정 이유까지 완성된 팀
6. `completed`: 기존 JSON API와 같은 전체 최종 결과
7. `error`: 실행 중 실패한 단계와 오류 메시지

팀 이벤트의 `team_name`은 갱신 키이고 `version`은 `1`, `2`, `3` 순서입니다. 백엔드는 같은 `team_name`의 최신 버전을 저장하고 프론트에 중계합니다.

```text
id: 4
event: team_preview
data: {"job_id":"job-id","team_name":"팀 1","team_index":1,"total_teams":4,"version":1,"team":{...}}

```

AI 서버는 중간 이벤트를 별도로 저장하지 않습니다. 연결 종료 후 재접속과 중간 결과 복구는 백엔드가 `job_id`를 기준으로 담당하며, AI 작업은 스트림 소비자가 연결을 종료해도 최종 저장까지 계속 실행됩니다. 15초 동안 이벤트가 없으면 `: keep-alive` heartbeat가 전송됩니다.

## 내가 구현하면서 집중한 부분

이 프로젝트의 AI 파트를 구현하면서 특히 신경 쓴 부분은 아래와 같습니다.

- 학생 역량을 단순 점수가 아니라 실제 프로젝트 기여 가능성 기준으로 해석하도록 설계
- 기술 역량과 협업 성향을 함께 고려하는 팀 매칭 구조 구현
- 팀 생성 후 검증과 재조정 루프를 통해 결과 안정성 강화
- 관리자 프롬프트 기반 재생성 기능으로 실사용성 개선
- 최종 결과를 프론트에서 바로 활용할 수 있도록 팀 요약 데이터 제공

## 기대 효과

이 AI 시스템을 통해 팀 편성 과정의 수작업 부담을 줄이고, 보다 공정하고 균형 잡힌 캡스톤 프로젝트 팀 구성이 가능하도록 만드는 것을 목표로 했습니다.
